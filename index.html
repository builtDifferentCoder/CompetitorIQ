What it does

Give it a company name. A planner agent breaks the research into four angles — pricing, features, customer sentiment, and recent news. A person reviews that plan before anything runs, can remove a task, then approves it. Four researcher agents go out in parallel, each grounded in real web search, and a writer agent synthesizes their findings into a report where every claim is numbered and traceable to a source. Before the report is final, the person reviews the draft too — approve it, or send it back with a note for revision, as many times as needed.

  • 01
    Plan The planner agent reads the company name and proposes four structured research tasks across strategic domains.
  • 02
    Checkpoint 1 — Approve the plan Execution halts cleanly via LangGraph interrupt(). A human reviewer can drop tasks or refine the scope before real search API spend occurs.
  • 03
    Research, in parallel Four worker agents execute concurrently via dynamic fan-out, extracting verified findings with deterministic corroboration confidence scores.
  • 04
    Write & Ground A writer agent synthesizes all parallel findings into an intelligence report with numbered source citations and a verifiable references section.
  • 05
    Checkpoint 2 — Approve the draft Execution pauses once more. The human can approve the final report or request iterative revisions with custom notes before sign-off.

Decisions worth explaining

The interesting part of a multi-agent system is rarely the happy path. These are the places where the first version broke, and what that led to.

state

Four agents writing to one list, safely

Four researchers finish in whatever order the web answers them, and all four need to land in the same state without overwriting each other. The findings field uses an operator.add reducer so concurrent writes merge instead of racing. Verified by running the fan-out three times in a row and asserting the result count matches every time — a race condition can pass once and fail the next run, so one green run proves nothing.

checkpointing

The interrupt that didn't survive a restart

Pausing for human approval relies on LangGraph persisting state at the pause point, then rehydrating it later — not a thread sitting in memory. The first checkpointer (in-process memory) looked like it worked, until a test that killed the process between pause and resume showed the state was gone. Switched to a disk-backed SQLite checkpointer in WAL mode before that reached production, not after.

trust

A confidence score that meant nothing

Early researcher output included a confidence number the model generated alongside its findings — a plausible-looking float with no real signal behind it. Replaced with a deterministic score computed from how many corroborating sources were actually found, capped below full certainty on principle: an automated search pipeline with no human verification shouldn't claim near-certainty.

grounding

Every claim traces to a source

The writer agent is prohibited from stating anything that isn't backed by a specific finding — if the research doesn't support a claim, the claim is left out rather than filled in from the model's own training knowledge. The final report carries numbered citations and a references list, so any claim can be checked against where it came from.
